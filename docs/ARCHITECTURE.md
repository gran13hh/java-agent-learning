# 架构与设计边界

## 请求与持久化

```text
浏览器 → Controller → Service → Repository → MySQL
                         ├─ AI 网关 → 聊天 / Embedding API
                         ├─ 知识检索 → MySQL 向量 → Java 余弦相似度
                         └─ Agent → 受控工具执行 → 持久化运行记录
Redis：题库缓存与请求限流；MySQL 保留缓存版本与持久化请求预算
```

Controller 负责参数校验和 HTTP 映射，Service 负责业务状态与事务，Repository 使用参数化 SQL。数据库由管理脚本建表，应用账号只授予业务库的 DML 权限。模型网络请求不放在长时间持有数据库锁的事务中。

题目、面试轮次与回答、反馈任务、知识文档与片段、Agent 运行与步骤均保存在 MySQL。反馈保存引用片段快照，避免后续修改资料改变历史反馈的依据。回答先保存，再申请生成反馈；模型失败不会丢失作答。

## RAG

导入接口接收不超过 6000 字符的文本，应用分块后单独建立向量索引。原文与向量均存 MySQL，检索时读取兼容的就绪片段，在 Java 内存中计算余弦相似度；重启应用无需重新向量化。

当前最多读取 2000 个兼容片段，取相似度不低于 0.35 的前 3 项，适用于小规模资料库。索引绑定向量模型地址、模型名和维度，配置变更后需要重新建立索引。该实现没有专用向量数据库或近似最近邻索引。

没有合适片段时返回空命中，并将证据不足传递给生成环节。系统不将空检索结果包装成资料引用；普通知识性建议与基于导入资料的结论需要区分。检索成功也不等于生成内容必然正确，仍需核对引用与结论。

## 受控 Agent

Spring AI 提供模型与原生工具调用适配，应用显式执行循环。模型只提出工具请求，Java 校验名称与参数后调用白名单工具：

| 工具 | 边界 |
| --- | --- |
| `list_questions` | 按主题读取最多 5 道题目 |
| `search_knowledge` | 检索已索引资料，查询长度最多 500 字符 |
| `read_interview` | 只读取本次运行选定的面试；未选择时明确返回缺少依据 |

每次运行最多 3 次模型尝试、3 次工具请求和 90 秒执行预算；单次模型 HTTP 超时不超过 45 秒。工具均为读取操作，模型不能直接执行 SQL 或修改业务记录。

创建运行使用客户端 UUID `requestId` 实现幂等，运行状态与步骤持久化。执行接口同步运行任务，失败不会自动重试。运行租约到期后读取状态会显示 `INTERRUPTED`，当前没有后台恢复执行器。

## 缓存与限流

题库仅缓存第 1 页、每页 5 或 20 条的常用查询。题目写入与 MySQL 缓存版本更新处于同一事务；Redis 缓存键包含版本号，旧请求回填旧版本不会覆盖新版本。TTL 为 60～75 秒。命中缓存仍需查询数据库版本，Redis 不可用时回退 MySQL。

聊天和向量 API 分别限制为连续 60 秒内最多 5 次请求。先经过 Redis Lua 滑动窗口，再由 MySQL 持久化预算校验，防止 Redis 重启或数据丢失放宽额度。Redis 不可用时拒绝外部模型请求。已经发出的失败请求也计入预算，不自动重试；上游限流的等待信息持久化保存。

## SSE 进度

`GET /api/agent/runs/{id}/events` 仅观察运行，不触发模型调用。服务端每秒读取数据库，状态变化时发送完整快照，并发送心跳；完成后关闭连接。每个应用实例最多同时观察 20 个连接。

这是运行状态推送，不是模型逐 Token 输出。浏览器重连读取最新快照，不重发执行 POST，也没有按 `Last-Event-ID` 回放完整历史事件的机制。持久化步骤可以通过运行详情接口重新查看。

## 运行边界

默认绑定本机地址，定位为单用户演示。当前没有用户鉴权、跨用户数据隔离或分布式任务调度；公开部署前需要补齐这些能力。请求预算、执行步骤和固定评测提供可检查的行为记录，不代表已经验证生产吞吐量或模型总体准确率。
